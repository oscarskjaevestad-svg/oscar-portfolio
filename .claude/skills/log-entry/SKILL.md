# A log entry on oscarns.com

The site is static HTML generated by Python in `tools/sitegen/`, and the
generated pages are committed. Vercel deploys `main` within seconds of a
merge and builds a preview for each PR. The look is fixed in `DESIGN.md`:
read it before touching anything visual.

## Rules that are not up for debate

1. **Nothing private.** No IP addresses, host names, tailnet names, ports,
   notification topics, tokens, or anything about the household: who lives
   there, the address, the network, routines, or what the cameras and
   microphones see. Describe a setup ("a camera on the printer, a
   detector on my own server, alerts to my phone") rather than where it
   lives. `tools/check_public.py` catches the mechanical cases, but you're
   the check for the rest.
2. **Photos have no metadata.** Always go through `tools/photo.py`. Phone
   photos carry GPS coordinates. Look at every photo before using it: no
   faces except the user's own, no screens showing addresses or URLs, no
   windows that show where the house is, no documents.
3. **True, and measured.** The log is "what broke, what I measured, and what
   I changed". Use real numbers from the work. Never invent a result, and
   say plainly what hasn't been tested yet. If something is planned, say
   it's planned.
4. **The user approves the text before the PR,** and merges it themselves.

## Voice

Read the newest entry in `tools/sitegen/page_articles.py` first, and match
it:
- first person, plain words, short paragraphs;
- the problem, then the measurement, then the change;
- one `lesson(...)` box at the end;
- no hype, no emoji, sentence-case headings.

Every string has an English and a Norwegian version: `t(en, no)`, `p(en,
no)`, `h2(en, no)`. Write the Norwegian as a native speaker would, not as a
word-for-word translation, with Norwegian number formats (`0,055 mm`,
`20 %`, `≈ 25 t`). The feed is English only.

## Steps

### 1. Agree the story

Before writing, give the user a five-line outline: title, the one-sentence
summary, three or four section headings, and the lesson. Ask which photos
they have. Get a yes on the outline.

### 2. Photos

```bash
~/.venvs/site/bin/python tools/photo.py ~/Downloads/IMG_1234.HEIC log/img/short-name.jpg
~/.venvs/site/bin/python tools/photo.py ~/Downloads/IMG_1235.jpg log/img/other.jpg --focus 0.3
```

Every photo comes out upright, 1600 × 1067 and stripped. `--focus` chooses
which part survives the crop to 3:2 (0 = top, 1 = bottom). Open each result
and look at it. If `~/.venvs/site` is missing:
`python3 -m venv ~/.venvs/site && ~/.venvs/site/bin/pip install pillow pillow-heif`.

In the page: `photo("img/short-name.jpg", "<English alt text describing
what's in it>", "<English caption>", "<Norwegian caption>")`.

### 3. Write the page

In `tools/sitegen/page_articles.py`, add a constant next to the other log
entries:

```python
NEWNAME = page(
    "slug-with-dashes", "log",
    ("English title", "Norsk tittel"),
    "One-sentence English summary (also the meta description).",
    ("Log", "Logg", "log"), ("MM.YYYY", "MM.YYYY"),
    ("English lead paragraph.", "Norsk ingress."),
    f'''
    {figures([...])}            # optional: 3-4 real numbers
    {h2("...", "...")}
    {p("...", "...")}
    {photo(...)}
    {lesson("...", "...")}
    <p class="more">{t('<a href="../builds/inmoov.html">The InMoov hand build →</a>', '<a href="../builds/inmoov.html">Byggingen av InMoov-hånden →</a>')}</p>
''',
    prev=("previous-slug.html", ("Short previous title", "Kort forrige tittel")),
)
```

Then give the previous entry an `nxt=("slug-with-dashes.html", (...))` so
the two link to each other.

### 4. List it everywhere

The check in step 6 fails if any of these is missing:

| Where | What to add (newest first) |
|---|---|
| `tools/sitegen/build.py` | the import, a `"log/slug.html": NEWNAME` line in `pages`, and a `LOG` feed entry `(path, title, summary, "YYYY-MM-DD")` at the top |
| `tools/sitegen/page_index.py` | an `<article class="entry log-row">` at the top of the log list, `MM.YYYY` in the gutter, title and summary in both languages |
| `tools/sitegen/page_articles.py`, `FOLLOW` | an `<li>` at the top of "What's in it so far" |
| `sitemap.xml` | a `<url>` with `<loc>` and today's `<lastmod>` (this file is hand-written) |

If the entry changes a build's status (the InMoov stage, what Jarvis can
do), update `INMOOV` / `JARVIS` in `page_articles.py` too. The **Now board**
on the homepage reads `status.json`, which the Pi updates with
`tools/website_status.py` in the jarvis-lab repo (for example
`--inmoov-stage assemble`). It must always be true.

If you changed `style.css` or any `.js`, bump `VERSION` in
`tools/sitegen/parts.py`, so browsers fetch the new files.

### 5. Build

```bash
python3 tools/sitegen/build.py
```

Then check `git status`. Only the pages you meant to change, `feed.xml`
and maybe `vercel.json` (regenerated) should differ. The homepage changing
is expected when you added an entry. If the homepage's content changed in
other ways, the CV PDFs need `tools/build-assets.py` (Playwright).

### 6. Check

```bash
python3 tools/check_public.py
```

This checks for private addresses and host names in everything Vercel
serves, that every photo is 1600 × 1067 with no metadata, and that every
log page is listed in all four places. It must say `ok` three times.

### 7. Preview

```bash
python3 -m http.server 8765
```

Open `http://localhost:8765/log/slug.html` in the browser pane. Check:
- dark and light theme,
- English and Norwegian (the language toggle),
- phone width (375 px) and desktop,
- photos load and the captions are right,
- previous/next links work both ways,
- no errors in the console.

The server's assets are cached by `?v=VERSION`. If a script looks stale,
reload with the cache bypassed.

### 8. PR

Work on a branch, commit with the attribution line, and push to
`oscarskjaevestad-svg/oscar-portfolio`, which is this repo (Jarvis PRs go
to a different account). Give the user the PR link and the Vercel preview,
and wait for them to merge. After the merge, open
`https://www.oscarns.com/log/slug.html` and confirm it's live.
